## Reverse proxy

`supabase/functions/posthog-proxy` — deployed and smoke-tested against production:
- `GET /posthog-proxy/static/array.js` → 200, correct JS payload (asset-host routing confirmed)
- `POST /posthog-proxy/decide/` → PostHog's own `401 not_authenticated` response, i.e. the request reached PostHog, not a Supabase gateway error (main-host routing confirmed)

The client's `api_host` now points at this proxy automatically whenever `VITE_SUPABASE_URL` is set (always true in this app), falling back to `VITE_POSTHOG_HOST` then the direct EU host if it isn't.

One side effect of this test pass: a single `posthog_skill_verification_test` event was sent under `distinct_id: test_verification_only` to confirm the server-capture request shape is accepted by PostHog. Safe to ignore or delete from your PostHog project — it's clearly labeled and won't affect real funnels.

## Suggested dashboards / insights to build in PostHog

- **Signup → activation funnel**: `user_signed_up` → `checklist_created` → `checklist_completed` (first 7 days)
- **Kiosk daily-active-locations**: unique `location_id` properties on `kiosk_pin_unlocked`, trended daily
- **Billing funnel**: `checkout_started` → `subscription_activated`, broken down by `plan`
- **Churn signal**: `subscription_payment_failed` rate and `subscription_canceled` by `plan`
- **Team growth**: `team_member_invited` → `team_member_joined` conversion rate

## Anything skipped and why

- **CRA/legacy env pattern** — n/a, project is Vite-only.
- **Session replay / surveys** — not enabled; nothing in the discovery suggested a need, and it wasn't part of the approved taxonomy. Straightforward to add later (`posthog.init` option) if wanted.
- **`capture_exceptions`** — deliberately left off. Sentry already owns error tracking here (Hard Rule 6: don't duplicate existing tooling); enabling it would double-report every exception into both tools.
- **Distinguishing `checklist_created` vs `checklist_updated`** — only `_created` is captured, per the approved taxonomy. Edits still invalidate the query cache as before but don't fire an event.
