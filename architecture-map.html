Notable findings

Critical path

New user signup flows: Signup.tsx → supabase.auth.signInWithOtp → verifyOtp → AuthContext SIGNED_IN → fetchTeamMember → setup_new_organization RPC → navigate(/admin). Navigation deferred to useEffect to avoid ProtectedRoute race (line 39 Signup.tsx).

Architecture insight

AuthContext uses ONLY onAuthStateChange (not getSession + listener). Using both caused double-invocation of setup_new_organization on first load — a PK conflict bug fixed by this design (line 159, AuthContext.tsx).

Dead / mock data

admin-repository.ts exports initialLocations, initialStaffProfiles, initialTeamMembers, initialAuditLog (lines 162–346) — hardcoded mock data with French addresses. These are NOT used by any live page — the real data comes from Supabase hooks. Dead code risk: unused exports bloating the bundle.

Surprise: Kiosk is public

Kiosk (/kiosk) is NOT behind ProtectedRoute. It fetches checklists via the anon key RPC get_kiosk_checklists. Submits logs via submit_kiosk_log (SECURITY DEFINER). Staff PINs are hashed server-side. Org ownership stored in localStorage (kiosk_owner_user_id).

Surprise: setupError navigation

Admin.tsx must navigate BEFORE calling signOut (line 311-312). If signOut fires first, ProtectedRoute intercepts and redirects to /login before the .then() can reach /signup. The order matters — this is a React render-cycle trap.

Submission queue

submission-queue.ts implements an offline-resilient retry queue in localStorage (QUEUE_KEY="olia_pending_logs"). Max 10 attempts, 7-day TTL. Drained on every kiosk load (Kiosk.tsx line 439).

alerts-store.ts

alerts-store.ts is a pub/sub store kept for backward compat with tests. Real alerts come from the Supabase `alerts` table via useAlerts hook — NOT this store. The store's DEFAULT_ALERTS array is empty (line 15, alerts-store.ts).
